# Reading Desk

A personal, static news reader and learning journal. Aggregates headlines from The Atlantic, The Economist, The New York Times, The Wall Street Journal, and The Washington Post, and (in later phases) uses the Anthropic API to help decide what's worth reading and track what you're learning.

No backend, no build step, no framework — plain HTML/CSS/JS deployed on GitHub Pages. The app never fetches or stores full article text; it only ever shows headline + RSS summary + a link that opens the real article in your normal browser tab.

## Status: Phase 1

- **Today** — a plain chronological feed of the last ~7 days across all five outlets, filterable by source, searchable by headline/summary.
- **Settings** — a read-only mirror of the configured feeds (with last-updated time), Export JSON / Import JSON backup, and Clear all data.
- **This Week / Journal / Archive** — placeholders; curation, the reading journal, knowledge gaps, rituals, and the calendar view arrive in later phases.

## One-time setup after first push

1. **Enable GitHub Pages**: repo *Settings → Pages → Build and deployment → Source*: "Deploy from a branch" → Branch: `main`, folder: `/ (root)` → Save. The site will be live at `https://afang2026.github.io/newsproject/` within a minute or two.
2. **Enable Actions write permission**: repo *Settings → Actions → General → Workflow permissions* → select "Read and write permissions" → Save. This lets the scheduled feed-fetch workflow commit `feeds.json` back to the repo.
3. **Run the fetch workflow once**: *Actions tab → "Fetch feeds" → Run workflow*. It also runs automatically every 2 hours.

## Editing feeds

Edit [`feeds.config.json`](feeds.config.json) — each entry is `{ "source", "section", "url" }`. Push the change; the next run (scheduled or manually triggered from the Actions tab) picks it up. If a feed starts failing or returning zero items, `scripts/fetch_feeds.py` logs a `WARN:` line in that run's log instead of crashing — check the Actions tab's run output if articles from one outlet stop showing up. (The Washington Post's public RSS gateway was intermittently returning HTTP 502 at the time this was built — if it stays down, that outlet will just silently contribute nothing until its feed comes back or you swap in a different URL.)

## Backup and restore

Everything this app stores (settings now; your reading log, knowledge gaps, and topics in later phases) lives only in **this browser's** `localStorage`, under keys prefixed `rd.`. It is never synced anywhere and is lost if you clear browser data.

- *Settings → Export JSON* downloads a full backup.
- *Settings → Import JSON* restores from a backup file — this **overwrites everything currently stored**.
- Export regularly, and before clearing browser data or switching browsers/devices.

## Local development

There's no build step, but opening `index.html` directly via `file://` won't work — browsers block `fetch()` of local JSON files from a `file:` origin, so `feeds.json`/`feeds.config.json` won't load. Serve the folder instead:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000`.

## Project structure

```
index.html                     shell: header, tabs, modals
css/styles.css                 all styles, light/dark theme variables
js/state.js                    localStorage I/O, schema version + migrations
js/ui.js                       clock, theme toggle, tabs, collapsible cards, confirm modal
js/feeds.js                    loads feeds.json/feeds.config.json, search/filter/render
js/app.js                      wires the Today and Settings pages together
feeds.config.json              editable list of RSS feed URLs
feeds.json                     generated by the Action — do not hand-edit
scripts/fetch_feeds.py         fetches + normalizes + dedupes + 7-day-windows the feeds
.github/workflows/fetch-feeds.yml   runs the script every 2 hours and on demand
```
